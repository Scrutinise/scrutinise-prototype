## CONTEXT

Two categories of problem identified:

**Category A — Content fetched but incomplete (caselaw)**
TNA caselaw: 7,489 queue page-rows done, each page = 50 judgments = 374,450 expected.
Only 74,851 (~20%) in corpus_sections. 300k judgments are missing.
R2 has 149,702 keys (74,851 sections × 2 keys each = consistent with corpus_sections).
So the missing judgments never made it to R2 either — this is a processing failure, not
an R2→DB gap.

**Category B — Content never fetched (silent failures)**
FCA, ECHR, Hansard, Written Answers, Written Statements: queue rows marked `done`,
0 R2 keys, 0 corpus_sections. Workers claimed, ran, produced nothing, marked done.
Root cause unknown — could be: API endpoint changed, auth required, response format
changed, r2Exists() false positive, or worker error swallowed.

## PART 1 — Diagnose TNA caselaw gap (Category A)

### Step 1 — Sample failed judgment pages

```sql
-- Find caselaw queue rows and check for any error data
SELECT "docId", status, "lastError", "updatedAt"
FROM ingest_queue
WHERE corpus = 'tna-caselaw'
ORDER BY "updatedAt" DESC
LIMIT 20;

-- Check if any caselaw rows have lastError set
SELECT "lastError", COUNT(*)
FROM ingest_queue
WHERE corpus = 'tna-caselaw'
  AND "lastError" IS NOT NULL
GROUP BY "lastError"
ORDER BY COUNT(*) DESC;

-- What's the range of caselaw docIds in the queue?
SELECT MIN("docId"), MAX("docId"), COUNT(*) FROM ingest_queue
WHERE corpus = 'tna-caselaw';
```

### Step 2 — Sample one page and check what it returns

Read `scripts/ingest/sources/tna-caselaw.ts` — search for the function that processes
a page-row docId. Read only that function (~30 lines).

Then manually fetch one of the done page URLs to see what TNA returns:
```typescript

console.log('status:', res.status)

console.log('first 500 chars:', text.slice(0, 500))
// Count <entry> tags — should be 50
const entries = text.match(/<entry>/g)?.length ?? 0
console.log('entries on page 1:', entries)
```

### Step 3 — Check R2 for partial page content
```typescript
// List R2 keys under caselaw/ — are they evenly distributed across pages,
// or clustered at early pages?
const list = await r2.list({ prefix: 'caselaw/', limit: 10 })
console.log('sample keys:', list.objects.map(o => o.key))
// Then count total
const all = await r2.list({ prefix: 'caselaw/' }) // paginate
console.log('total caselaw R2 keys:', all.objects.length)
```

Report findings from all three steps before implementing any fix.

Expected outcomes:
- If pages beyond N return empty → TNA Atom feed is paginated differently than expected
  (e.g. max 1,500 pages × 50 = 75,000 judgments — which matches our 74,851 exactly).
  This would mean we've actually ingested ALL available judgments and 374k was a wrong estimate.
- If pages return 50 entries but only some are written to R2 → per-judgment processing
  is failing silently for ~80% of judgments. Need to find the error.
- If lastError shows a pattern → fix that error.
