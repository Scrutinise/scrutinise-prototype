## 3. Dataset A — Legislative Texts (`/node/1`)

### 3A. Version datasets offered

Six version-categories, each downloadable independently:

| Dataset | Description | Notes |
|---------|-------------|-------|
| **Enacted ePublished** | Electronically published original text, no amendments | Digital-era acts |
| **Enacted Printed** | Official print versions as laid before Parliament | Historical |
| **Revised All Versions** | All point-in-time historical versions of each act | Largest dataset |

**This is the same data as our existing TNA Changes API feed** (`/changes/affected/{actId}/data.feed`) but delivered as pre-paginated bulk XML — no Atom pagination needed. One file per year per legislation type. 5,570 effects across 32 UKPGA acts in the 2010 year-file.

**Includes:** EffectType (substituted, inserted, repealed, applied, word substituted, etc.), AffectedProvisions with section Refs and URIs, AffectingProvisions, CommencementAuthority, InForceDates with Qualification (including partial in-force, for-specific-purposes etc.), Applied/RequiresApplied flags, geographical extent.

**Does NOT include:** literal replacement text (the "for X substitute Y" prose) — same as TNA Changes API. That is still in the affecting provision's text, not here.

## 6. Query Builder (`/query-builder`)

### 6A. What it is

A web search tool for legislation text. **There is no standalone REST API** — the Query Builder IS the interface. Queries run against an internal database updated every 24 hours. Brief nightly downtime during update.

### 6B. Capabilities

- Full-text search across enacted, current, or point-in-time versions (`version=original|current|YYYY-MM-DD`)
- Type filtering: `type=ukpga`, `type=uksi`, `type=primary`, `type=secondary`, `type=eu`, individual types
- Proximity search: `20[licence,appeal]` (unordered), `20(licence,appeal)` (ordered)
- Element targeting: `title(pension)`, `subject[police,England]`, `para(confers-power=true)`, `annotation(type=F, repealed)`
- Counting: `count(total-paragraphs)`, `count(schedules)`, `count(total-amendments)`
- Grouping: `groupby=department`, `groupby=year`
- Boolean: AND, OR, NOT, comma (AND with lower precedence)
- Range queries: `year=2000`, `year>2010 && year<=2020`, `orderby=-year`
- Extent restriction: `extent=E`, `extent=E+W+*`
- Welsh search: `language=welsh`
- Returns document links to legislation.gov.uk, not raw text

### 6C. Verdict for Scrutinise

No programmatic API. Useful for ad hoc research and building the "Query Builder guide" feature for users, but cannot be used for automated ingest. The counts capability (`count(unapplied-effects)`, `count(prospective-paragraphs)`) has potential for corpus analytics.

### 8B. The Companies Act 2006 / empty-acts problem

**Confirmed solved by bulk download.** Companies Act 2006 (`ukpga/2006/46`) shows `Revised Current English: Yes` in the Legislation on Website CSV. The whole-act CLML is available in the "Revised Current" or "Best Collection" ZIP. This is a significant advantage over our per-section API approach.

The TNA per-section API returns HTTP 202 for large acts like Companies Act 2006 because it must generate the CLML on-demand for individual sections — but the bulk file was pre-generated. An estimated 21,850 sections from "empty acts" in our corpus would be recoverable via bulk download.

### 8C. XML schema comparison

| Dimension | Our per-section `.original.xml` / `.tna.xml` | Bulk "Revised Current" CLML |
|-----------|----------------------------------------------|-------------------------------|
| Format | CLML — P1group node extract | CLML — full whole-act document |
| Amendment markup | None (TNA-compiled output) | None (TNA-compiled output) |
| Contains `<Addition>/<Substitution>/<Repeal>` | No | No |
| Contains `<CommentaryRef>/<Commentary>` | Yes | Yes |
| Key scheme compatible | `/actId/sections/N.tna.xml` | Different — would need parsing |

**Important:** The bulk text gives the same TNA-compiled output as our per-section fetch — not original enacted CLML with amendment markup. The amendment markup issue discovered in V2.75 is not solved by switching to bulk. The Effects XML is still the source for amendment data.

### 8D. The 21,850 "neither" sections

Our corpus has approximately 21,850 sections with no XML in R2 (companies-act-class HTTP 202 problem). The Legislation on Website CSV confirms Companies Act 2006 Revised Current is available in bulk. To recover these sections, the approach would be:

1. Download Best Collection XML (1.32 GB) or Revised Current XML (2.44 GB)
2. Parse whole-act CLML to extract individual P1group/section nodes
3. Store as per-section keys matching our existing R2 scheme, or as whole-act keys under a new scheme

This is achievable but requires writing a CLML parser to extract section nodes from whole-act documents.

## 11. Gotchas

1. **Amendments data is 6 months old** (30 Oct 2025). Not on the daily cycle. For the most recent effects (Oct 2025 – May 2026), you still need to use the TNA Changes API per-act. The bulk amendments supplement but don't fully replace our effects ingest.

2. **Core LCRD is 13 months old** (Jun 2024). Legislation on Website CSV is the current alternative for document inventory.

3. **No per-act sub-downloads for text data.** Text data comes as monolithic ZIPs (all legislation types, all years). You cannot download just UKPGA. However, the Legislation on Website CSV can identify which acts within the ZIP are UKPGA, allowing selective extraction after download.

4. **Bulk text = whole-act CLML**, not per-section. Parsing required to extract individual section nodes. Our existing R2 key scheme (`/actId/sections/N.{original,tna}.xml`) stores per-section extracts. Switching to bulk requires either: (a) a CLML parser to extract sections, or (b) a new whole-act key scheme alongside the per-section one.

5. **No literal amendment text in Effects XML.** Same limitation as TNA Changes API — "for X substitute Y" language is in the affecting provision's prose, not in the effects data. The amendment-aware compiler still needs to parse affected provisions to extract replacement text.

6. **Auth required on every download.** HTTP Basic Auth (`-u research:n3w_s!te`) needed on all `/data/downloads/` paths. Embed in download script.

7. **No explicit rate limits observed.** HEAD requests to 15+ files in quick succession raised no 429. Large download presumed fine but not stress-tested.

8. **Statutory Powers & Duties (112 MB) is AI-extracted.** TNA flags it as potentially containing errors. Not reliable enough for the Lex citation use case without verification.

## 12. Phase 2 Proposed Plan (Planning Only — Not Executing)

### Architecture

**Download script:** `scripts/legislation/bulk-download.ts`

```typescript
// Structure:
// 1. Download Legislation on Website CSV → inventory of all 350,557 docs
// 2. Identify which have Revised Current = Yes
// 3. Download Best Collection XML ZIP (1.32 GB)
// 4. Extract and parse whole-act CLML → per-section nodes
// 5. Store per-section in R2 (matching existing key scheme where possible)
// 6. Download UKPGA all-years amendments ZIP
// 7. Parse effects XML → update Railway LegislationSection / LegislationItem
```

**Resume support:** curl `--continue-at -` for large ZIPs. Checkpoint file (`bulk-download-checkpoint.json`) tracking which ZIP files have been processed.

**R2 key scheme:**
- Bulk-sourced section XML matches existing: `{actId}/sections/{N}.tna.xml` (current) and `{actId}/sections/{N}.original.xml` (enacted)
- This requires parsing bulk CLML to extract P1group nodes — same keys, different ingestion path
- Alternative: store whole-act files at `{actId}/whole-act.tna.xml` as a separate key and update legislation-search to fetch whole-act then extract section on demand (avoids parsing 1.32 GB up front, adds latency on search)

### Wipe or merge?

**Merge, not wipe.** Our R2 already has 263,231 XML files (`{actId}/sections/N.{original,tna}.xml`) for ~116,110 sections. The bulk download would supplement:
- Acts missing from per-section API (Companies Act 2006 etc.) — new files
- Acts already ingested — overwrite with bulk versions (effectively a consistency check)

Recommended: check R2 existence before writing; only write if key is absent or if bulk date > existing file date.

### Side-by-side comparison before switching

Run a 5-act comparison: download Best Collection for the 5 acts already in V2.75-H4 verification (Equality Act, Theft Act, Income Tax Act, Finance Act 2024, Companies Act 2006). Parse bulk CLML, compare with our per-section R2 files. Check:
- Section numbering matches
- Content identical for acts with clean per-section ingest
- Companies Act 2006 sections appear in bulk where our R2 has gaps

### Database migration implications

**New fields potentially needed on LegislationSection:**
- `bulkSource: Boolean` — whether this section came from bulk download vs per-section API
- `bulkDownloadDate: DateTime` — when the bulk file was downloaded (for freshness tracking)

**New fields on LegislationItem:**
- `hasRevisedCurrent: Boolean` — from Legislation on Website CSV flag
- `inForceStatus: String` — from In Force Dataset (repealedBy / etc.)
- `inForceAffecting: String` — the repealing/amending act URI

**Migration:** `prisma db push` or `prisma migrate dev` — no breaking schema changes, additive only.

### Daily updates

**Text data** (Best Collection, Revised Current) is genuinely daily. Options:
1. Re-download entire ZIP daily (~1.32 GB) — simple but bandwidth-heavy
2. Use Legislation on Website CSV to identify changed acts (compare `Modified` dates if exposed) — targeted re-download
3. Continue using per-section TNA API for individual act updates; use bulk only for initial backfill of gaps

**Recommendation:** Use bulk for initial backfill of empty-acts (Companies Act 2006 class). Continue per-section API for ongoing daily updates. Re-download bulk amendments quarterly (given they're only updated ~quarterly anyway).

### Does bulk replace or supplement per-section ingest?

**Supplements, not replaces**, for our architecture:

| Use case | Per-section API | Bulk download |
|----------|----------------|---------------|
| Daily incremental updates | ✓ Best | — |
| Acts that return 202 (Companies Act) | ✗ Broken | ✓ Solves it |
| Non-UKPGA types (UKSI, ASP, etc.) | Partial (V2.75-H Phase 1 scope) | ✓ All 350,557 docs |
| Effects/amendments | ✓ Daily via TNA Changes API | ✓ But 6 months stale |
| Whole-act view | — | ✓ Best Collection |

Recommended strategy: **bulk download for initial backfill + gap-filling; per-section API for daily freshness**.

## 14. Explanatory Notes Coverage

*Verified 14 May 2026 — fetched Equality Act 2010 EN CLML and inspected research.legislation.gov.uk dataset pages.*

### 14A. Are Explanatory Notes in the bulk download?

**No.** The research.legislation.gov.uk bulk text datasets (`/node/1`) contain only legislative text — the main CLML document for each act. Explanatory Notes are a separate document type in TNA's schema and are not packaged in the Best Collection, Revised Current, or any other bulk text ZIP.

The `/data` page mentions "their accompanying explanatory documents" but this is describing legislation.gov.uk's general holdings, not a separate bulk download. There is no Explanatory Notes dataset on research.legislation.gov.uk.

### 14B. Where do Explanatory Notes live?

Separate URL per act: `https://www.legislation.gov.uk/{type}/{year}/{num}/notes/data.xml`

Example: `https://www.legislation.gov.uk/ukpga/2010/15/notes/data.xml`

This is a **public endpoint** (no auth required) on legislation.gov.uk.

### 14C. CLML schema for Explanatory Notes

Root element is `<EN>` (not `<Legislation>`), schema: `http://www.legislation.gov.uk/schema/en.xsd`

```xml
<EN xmlns="http://www.legislation.gov.uk/namespaces/legislation"
    xml:base="http://www.legislation.gov.uk/id/ukpga/2010/15"
    DocumentURI="http://www.legislation.gov.uk/ukpga/2010/15/notes">
  <ukm:Metadata>
    <dc:title>Explanatory Notes to Equality Act 2010</dc:title>
    <dc:creator>Government Equalities Office</dc:creator>
    <dc:modified>2020-04-21</dc:modified>
    <ukm:ENmetadata>
      <ukm:DocumentClassification>
        <ukm:DocumentMainType Value="UnitedKingdomPublicGeneralAct"/>
        <ukm:DocumentStatus Value="final"/>
      </ukm:DocumentClassification>
    </ukm:ENmetadata>
  </ukm:Metadata>
  <ExplanatoryNotes>
    <ENprelims>
      <Title>Equality Act 2010</Title>
      <DateOfEnactment>8 April 2010</DateOfEnactment>
    </ENprelims>
    <Body>
      <Division id="d00001">
        <Title>REVISION NOTES</Title>
        ...narrative text...
      </Division>
    </Body>
  </ExplanatoryNotes>
</EN>
```

**Structure:** `<EN>` → `<ukm:Metadata>` + `<ExplanatoryNotes>` → `<ENprelims>` + `<Body>` → `<Division>` → narrative paragraphs. The notes contain `<Para><Text>` blocks with `<Citation>` cross-references to the act's sections.

Equality Act 2010 EN: 9,968 lines. Substantial — approximately the same length as a short act.

### 14D. Coverage and availability

- Available for all primary legislation from 1988 (same scope as Enacted ePublished digital text)
- Available for some secondary legislation
- No EN exists for very old acts (pre-digital)
- Separate PDF also available: `/{type}/{year}/{num}/pdfs/{id}_en.pdf`
- No bulk download exists — must fetch per-act

### 14E. What Explanatory Notes are good for

- Human-readable rationale for each section ("what does this provision do?")
- Cross-references to the policy intent behind specific subsections
- Context for AI summarisation of section text
- Currently NOT in our corpus at all — would require a separate ingest pass

### 14F. Ingest approach (for planning)

```
URL: https://www.legislation.gov.uk/{actId}/notes/data.xml
Rate: same throttle as section API (~200ms/act)
Storage: R2 key {actId}/notes.xml
Schema: EN root, different from Legislation root
Parser: separate from section CLML parser — EN uses Division/Para structure
Coverage: 1988+ primary legislation only (same as our per-section digital coverage)
```

No auth needed. EN can be fetched in the same ingest pass as sections, or as a separate post-process.

**Target:** Phase 3 ingest task (after bulk text and amendments are ingested). One pass over the 12,009 UKPGA acts to fetch and store `/notes.xml`.

## 15. In Force Dataset — Commencement Granularity

*Verified 14 May 2026 — inspected `result_table_aep_apgb_ukpga.csv` (33,060 rows) and `result_table_uksi.csv` (146,626 rows).*

### 15A. Column structure

| Column | Content |
|--------|---------|
| `item` | URI of the legislation item (act or provision) |
| `type` | Legislation type code (ukpga, aep, apgb, uksi, etc.) |
| `year` | Year of the legislation |
| `number` | Provision number (blank for whole-act entries, numeric for section-level entries) |
| `title` | English title |
| `status` | Current in-force status code (see 15B) |
| `affecting` | URI of the repealing/revoking instrument (blank when `affecting` is empty — no cross-reference recorded) |

### 15B. Status codes

**UKPGA/AEP status codes** (33,060 rows):

| Status | Count | Meaning |
|--------|-------|---------|
| `repealedBy` | 27,895 | Fully repealed by another instrument |
| `InForce` | 4,566 | Currently in force |
| `repealedWithSavingsBy` | 357 | Repealed with savings |
| `LimitedApplication` | 121 | Applies only in limited circumstances |
| `repealedByLegislature` | 28 | Repealed by devolved legislature |
| `CoreOnly` | 22 | Only core text in force (other provisions repealed) |
| `UnknownStatusPDFOnly` | 18 | Status unknown — only PDF available |
| `determinedBy` | 17 | Status determined by another instrument |
| `repealedEWBy` | 13 | Repealed in England and Wales only |
| `NIUnknownStatus` | 10 | Status unknown in Northern Ireland |
| `Expired` | 6 | Time-limited act that has expired |
| `Prosp` | 5 | Prospective — has Royal Assent but not yet in force (awaiting commencement order) |
| `repealedEBy` | 1 | Repealed in England only |
| `repealedEWNIBy` | 1 | Repealed in E+W+NI but not Scotland |

**UKSI status codes** (146,626 rows) — more granular jurisdiction tracking:

`InForce`, `CoreOnly`, `revokedBy`, `UnknownStatusPDFOnly`, `Spent`, `InForce1991`, `supersededBy`, `revokedWithSavingsBy`, `revokedEWSBy`, `revokedEBy`, `revokedSBy`, `revokedWBy`, `revokedEWBy`, `revokedEWNIBy`, `revokedProspBy`, `Expired`, `revokedWithSavingsSBy`, `Quashed`, `revokedNIBy`, `revokedWithSavingsEWSBy`, `revokedENIBy`, `revokedWithSavingsEWBy`, `revokedWithSavingsNIBy`

### 15C. Granularity: act-level or section-level?

**Primarily act-level for modern legislation.** The Equality Act 2010 (`ukpga/2010/15`) has exactly **1 row** in the dataset — one entry for the whole act, status `InForce`, `affecting` empty.

**Section-level granularity exists for ancient surviving provisions.** Ancient acts (AEP type) where individual provisions have survived while others were repealed have separate rows per provision. Example — Statute of Marlborough 1267 (`aep/Hen3/52/stat-marlbr`):

| Item URI | Number | Status |
|----------|--------|--------|
| `.../stat-marlbr` | (whole act) | — (multiple rows for different sections) |
| `.../stat-marlbr/1` | 1 | InForce |
| `.../stat-marlbr/4` | 4 | InForce |
| `.../stat-marlbr/15` | 15 | InForce |
| `.../stat-marlbr/23` | 23 | InForce |

For modern UKPGA: **0 rows with section-level URIs**. The InForce dataset does NOT record section-level commencement for modern acts.

### 15D. Jurisdiction-specific in-force status

**Yes, partially.** The dataset has jurisdiction-specific status codes: `repealedEWBy`, `repealedEBy`, `repealedEWNIBy`, `NIUnknownStatus` for UKPGA. For UKSI, the jurisdiction coverage is very granular (E, W, S, NI, EW, EWS, EWNI, ENI, ENS combinations in revocation codes).

**Critical limitation for the NI partial-enactment problem:** These jurisdiction codes only capture the REPEAL/REVOCATION end-state. They do NOT capture partial commencement — i.e., whether an act came into force in E+W but is still awaiting commencement in NI. The `InForce` status for the Equality Act 2010 has no jurisdiction qualifier — you cannot determine from this dataset whether all sections are in force in NI.

### 15E. Commencement orders as separate instruments?

**No.** The dataset records only the current end-state. The `affecting` column references the repealing/revoking instrument (for `repealedBy` etc.) but:

- For `InForce` rows, `affecting` is empty — no reference to the commencement order
- There are no commencement-date columns
- There is no record of the commencement order instrument that brought the act into force
- Partial commencement (different sections in force from different dates) is not captured

The `Prosp` status (5 rows, including Easter Act 1928 and several 2024 acts) does correctly flag acts with Royal Assent but no commencement order yet. This is useful for alerting users.

### 15F. Verdict for Northern Ireland partial-enactment problem

The InForce Dataset **does not solve the NI partial-enactment problem**.

What IT provides:
- Whether a whole act is in force, repealed, or prospective (act-level only for modern UKPGA)
- Whether a SI/SR was revoked in specific jurisdictions
- Useful for "is this act still good law?" queries

What it does NOT provide:
- Which sections came into force in NI (vs E+W)
- When each section came into force
- The commencement order reference

The source of truth for section-level NI commencement is the **Effects XML** — specifically `<InForceDates>` and `AffectingEffectsExtent` attributes in the amendments data. The Effects XML (Dataset B) records which commencement order activated which provision, with date and geographical extent. This is the correct data source for the NI problem.

## 16. Historical Act Coverage — The 7,634 Problem

*Verified 14 May 2026 — analysed Legislation on Website CSV (12,020 UKPGA rows).*

### 16A. UKPGA digital coverage by era

| Era | Total UKPGA | With XML (Revised Current or Enacted ePublished) | Print/PDF only | Coverage |
|-----|------------|--------------------------------------------------|----------------|----------|
| pre-1800 | 0 | 0 | 0 | N/A (these are AEP/APGB type, not UKPGA) |
| 1800–1900 | 5,068 | 794 | 4,274 | 16% |
| 1901–1987 | 5,378 | 2,019 | 3,359 | 38% |
| 1988+ | 1,574 | 1,573 | 1 | 100% |
| **Total** | **12,020** | **4,386** | **7,634** | **36%** |

### 16B. What "print/PDF only" means

Acts with only `Enacted Printed English: Yes` were digitised from physical print sources but are not available as machine-readable CLML XML. They are accessible via legislation.gov.uk as scanned/PDF documents only. The `enacted-printed` dataset on research.legislation.gov.uk returned 404 for CLML format (confirmed in Phase 1).

These 7,634 acts are genuinely unmapped for XML-based machine processing.

### 16C. Test case: Sale of Arsenic Regulation Act 1851

Selected from the 1800s UKPGA list. Result: `Enacted ePublished English: Yes`, `Revised Current English: No`.

**This act IS in the bulk XML download** (as its original enacted text). It was digitally published by TNA — the original enacted CLML is available. However, no revised/amended current version exists in the bulk, meaning only the original 1851 text is retrievable (which may be entirely superseded or repealed).

**Key clarification:** The 794 1800s acts with XML coverage (16%) include some Victorian-era acts that TNA did digitally publish their enacted text for. They do not have Revised Current versions (TNA has not maintained them), but the original text exists in CLML.

### 16D. Does bulk download solve the historical-coverage problem?

**Partially, not fully.**

| Population | Count | Bulk XML helps? |
|-----------|-------|----------------|
| Modern acts (1988+) returning HTTP 202 (e.g. Companies Act 2006) | ~21,850 sections | ✓ YES — solved by Best Collection XML |
| Victorian/Edwardian acts with Enacted ePublished digital text | ~794 1800s + ~2,019 1900–1987 | ✓ YES — original enacted text available |
| Pre-digital acts with print/PDF only | 7,634 | ✗ NO — no machine-readable XML in bulk |

The 7,634 print-only acts are not solvable by any bulk download. They would require either:
1. TNA digitising them (unlikely for repealed Victorian local acts)
2. OCR of the PDF scans (error-prone, not worth it for mostly-repealed historical acts)
3. Accepting them as out-of-scope for the XML corpus

**Recommendation:** Mark the 7,634 print-only UKPGA acts as permanently excluded from the XML ingest. Store their metadata (title, year, type, in-force status) in Railway but do not attempt XML section ingest.

### 17B. UKSI characteristics

UKSI are not revised the same way as primary legislation. When a UK Statutory Instrument is superseded, a new SI is made; the old one is simply revoked. So `Revised Current English: Yes` applies to only 8,812 UKSI (8%) — those that TNA has maintained a consolidated view for (typically important structural instruments like the SI Regulations themselves).

The other 99,986 UKSI in Best Collection provide the enacted original text.

### 17C. NI / devolved instruments — strong Revised Current coverage

NIA (95%), ASP (99%), ANAW (100%) all have strong Revised Current coverage — better than UKPGA (40%). These are smaller corpora maintained carefully by TNA and the devolved administrations.

NISR (NI Statutory Rules): 18,463 entries but no Revised Current breakdown was checked in this phase — treated as enacted-only similar to UKSI pattern.
