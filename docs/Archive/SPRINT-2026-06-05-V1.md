## PART 3 — Single-worker discovery (fix thundering herd)

### Problem
When queue empties, all 20 workers call discoverForCorpus() simultaneously.
For TNA sources, 20 concurrent enumerations hit the same rate limit → 30s backoff.

### Fix — DB lock for discovery

In `scripts/ingest/shared/queue-client.ts`, add a discovery lock function:

```typescript
// Only one worker runs discovery at a time.
// Uses a simple DB row as a mutex — worker that gets it runs discovery,
// others skip and sleep normally.
export async function acquireDiscoveryLock(workerId: string): Promise<boolean> {
  try {
    await getPool().query(`
      INSERT INTO scheduler_lock (id, locked_at, process_id)
      VALUES (2, NOW(), $1)
      ON CONFLICT (id) DO UPDATE
        SET locked_at = NOW(), process_id = $1
        WHERE scheduler_lock.locked_at < NOW() - INTERVAL '10 minutes'
    `, [workerId])
    const res = await getPool().query(
      'SELECT process_id FROM scheduler_lock WHERE id = 2'
    )
    return res.rows[0]?.process_id === workerId
  } catch { return false }
}

export async function releaseDiscoveryLock(workerId: string): Promise<void> {
  await getPool().query(
    'DELETE FROM scheduler_lock WHERE id = 2 AND process_id = $1',
    [workerId]
  ).catch(() => {})
}
```

Note: scheduler_lock table already exists (id=1 for scheduler). Use id=2 for discovery lock.
The 10-minute timeout ensures the lock auto-expires if a worker crashes mid-discovery.

In `worker-queue.ts`, wrap the discovery block:

```typescript
// Only attempt discovery if we can acquire the lock
if (pending === 0) {
  const hasLock = await acquireDiscoveryLock(workerId)
  if (!hasLock) {
    // Another worker is discovering — sleep and retry
    await new Promise(r => setTimeout(r, 30_000))
    continue
  }
  try {
    // ... existing discovery loop ...
  } finally {
    await releaseDiscoveryLock(workerId)
  }
}
```
