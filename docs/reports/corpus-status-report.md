## Purpose

A re-runnable workbook giving the current state of every ingested corpus at **organisation /
collection level**, for triage and reporting. It is a status instrument, not a data extract.

## The grain rule (non-negotiable)

**Org / collection level, never section level.** Every row in every tab is a corpus, an
organisation, or a collection. Section and word counts appear only as aggregate *columns*. No
tab lists an individual document, section, speech or judgment. The workbook must stay small
enough to open and skim; the corpus is ~17.9M sections and listing them is never the point.

## How to run

```bash
cd scripts/reports
npm install          # first time only — own node_modules, see "Why its own project"
npm run corpus-status
```

Output: `docs/reports/output/corpus-status-<YYYY-MM-DD>.xlsx` (re-running on the same day
overwrites that day's file).

### Inputs

| Input | Source | Notes |
|---|---|---|
| `corpus_targets` | corpus DB (`NEON_DATABASE_URL`, read from `scrutinise-web/.env`) | the registry — display label, estimate, priority, blocked, retired |
| `corpus_sections` | same | actual counts, licence, jurisdiction, compiled status, first/last ingested |
| `source_status` | same | circuit-breaker state per source |
| `ingest_queue` | same | done / failed / skipped counts |
| `docs/QUANGO_UNIVERSE.csv` | generated by `scripts/ingest/enumerate-quangos.ts` | 1,255 orgs, measured 2026-06-12 |
| `stat_dataset` / `stat_series` / `stat_observation` | **stats DB** (`STATS_DATABASE_URL`, from `scripts/stats/.env`) | Statistics tab only; optional |

Everything is **read-only**. The generator never writes to any database.

## Tabs

| Tab | Grain | Rows (2026-08-03) |
|---|---|---|
| **Summary** | one metric per row | 15 |
| **Corpus Status** | one non-retired corpus | 70 |
| **Quangos** | one gov.uk organisation | 1,255 |
| **Inquiries & Reviews** | one corpus | 3 |
| **Regulators & Ombudsmen** | one corpus | 10 |
| **Parliamentary** | one corpus (tier = parliamentary) | 21 |
| **Gaps & Pending** | one issue | 15 |
| **Statistics** | one stats dataset | 7 |

The three themed tabs (Inquiries, Regulators, Parliamentary) are **subsets of Corpus Status with
identical columns**, so a reader can compare like with like. Parliamentary is derived from
`tierFor()` in `scripts/ingest/search/corpus-map.ts` — imported, not duplicated, so the tab
cannot drift from the tier map that search uses. Regulators and Inquiries are explicit corpus-key
sets at the top of the generator (`REGULATORS`, `INQUIRIES`); **add new corpora there** or they
will appear only in Corpus Status.

### Corpus Status columns

Corpus key · Display label · Tier · Jurisdiction · Priority · Est. sections · Est. confirmed ·
Actual sections · Compiled · Compiled % · vs estimate % · Words · Licence · Breaker state ·
Trip reason · Queue done / failed / skipped · Blocked · Blocked reason · First ingested ·
Last ingested · Notes.

`vs estimate %` is the honest-denominator column: actual against the confirmed or estimated
universe, so under-ingestion is visible rather than implied.

### Gaps & Pending — what it detects

1. **Tracked but no content** — in `corpus_targets`, absent from `corpus_sections`.
2. **Content but untracked** — the reverse; means a corpus was seeded without a registry row.
3. **Blocked** — `corpus_targets.blocked`, with reason.
4. **Breaker not OK** — `source_status.state <> 'ok'`.
5. **Queue failures** — `ingest_queue` rows in `failed`.
6. **Licence gap** — corpora whose sections carry a null or `pending-verification` licence.
   A value like `(none) | opl-3.0` means the corpus is **mixed**: some rows licensed, some null.

## Statistics tab — deliberate scope limit

Dataset-level only: dataset id, source, title, licence, cadence, series count, observation
count, date span, last refreshed. **Time-series values are deliberately not folded in** (brief
§1.1). If the stats DB is unreachable or `STATS_DATABASE_URL` is unset, the tab is skipped with
a note in Summary — it never fails the run, because the corpus report must not depend on the
statistics layer being up.

## Why its own npm project

`scripts/reports/` has its own `package.json`/`node_modules`, mirroring `scripts/stats/`. The
generator needs `xlsx`, and `scripts/ingest` is the package deployed to Railway as the ingest
service — adding a report-only dependency there would bloat the production image for something
that only ever runs locally.

## Known limitations

- **Quango figures are a June 2026 measurement, not live.** Re-run
  `scripts/ingest/enumerate-quangos.ts` to refresh `QUANGO_UNIVERSE.csv`. A document tagged to N
  organisations is counted once per organisation, so the per-org `Total docs` sum overstates the
  distinct universe — stated on the Summary tab too.
- **`REGULATORS` / `INQUIRIES` are hand-maintained sets.** There is no body-type column in
  `corpus_sections` to derive them from.
- Retired corpora are excluded from Corpus Status (14 of the 84 `corpus_targets` rows).
