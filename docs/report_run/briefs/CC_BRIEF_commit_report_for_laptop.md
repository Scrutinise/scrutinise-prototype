## Step 4 — if anything in Step 2 is ignored

**Stop and report, with the rule and the files.** Then wait.

There are two ways to fix it and they are not equivalent, so Charlie decides:

1. **`git add -f <path>`** — commits the file, leaves `.gitignore` alone. The next file of the same kind is ignored again. Fine as a one-off, a trap as a habit.
2. **Amend `.gitignore`** with a negation, e.g. `!docs/report_run/report_src_v2/*.pdf` — permanent, and means future builds commit without anyone remembering to force them.

**Recommendation: (2) for the built PDFs and docx, because this will happen every time the report is rebuilt**, and (1) for the two large companion files in `appendices/`, because those are one-off artefacts rather than a recurring output.
