## 1. Where the brief's premises met the data

Five things the data said that the brief (or the S27 spec it inherits) did not. None blocks the work; each changed a decision.

1. **The four effect types are 100% official.** `amends`, `repeals`, `commences`, `modifies` come only from `tna-bulk-amendments` and `tna-inforce-dataset`. For all five named Acts the effect-type split is **one source, 100% official**. The two-source split the brief is built around exists only for `made-under` and `cites`, which are our extraction. The reader supports both (`edge_types`), and the default stays amends / repeals / modifies as S27 §5 and the brief's "expected shape" have it. `commences` is opt-in: on a heavily commenced Act it would crowd the answer.
2. **"Our own extractions carry the sentence that produced them" is true of one of the two.** `made-under` keeps a stored phrase (every row has one; the longest is 179 characters, so **it may be cut short** — I have not verified whether the extractor truncates). **`cites` rows in `legislation_edges` keep no text at all — 0 of 121,279.** The citing sentence lives in `citation_edge.citation_text`, which this reader does not join. So `quote` is non-null only for an extracted `made-under` row, is labelled `preamble-words`, and every other row carries `quote: null`. Official rows' `detail` is structured (`date|qualification|flag`) and is returned as `inForce`, never as a quotation.
3. **`sub_type` is a wider problem than `amends`.** `repeals` holds `power to amend or repeal conferred`, `ceases to have effect`, `expires`, `implicit repeal`; `modifies` holds 23,278 rows with **no recorded type at all**. The classifier covers every type, not only `amends`.
4. **A provision query has to return Act-wide rows, marked.** Effects recorded against the Act as a whole bear on every section. Folding them into "section 149: 5 amends" would tell a clerk the section was amended five times when all five are on the whole Act. This was my own first output; the check did not fail on it — I caught it reading G1's printed counts — and G1 now asserts the split. The headline reads `section-149: 0 (+5 on the whole Act) amends`.
5. **The string "held but not yet reachable" is not in the repository.** The sentence a drafting output actually carries is `describeCoverage()`'s *"We hold … — but not in this search, so they are not joined into any number here."* It is still accurate for the consequences numbers and I did **not** change it: wiring effects into the drafting output is not in this brief's scope (see §6).

## 3. Worked example — an `excluded` row is not presented as a textual change

Human Rights Act 1998 **section 3** (the interpretive obligation). The record holds an `amends` row from the **Victims and Prisoners Act 2024, section 69**, with `sub_type = "excluded"`.

**Reader** (`effectsFor`): `edgeType: amends`, `subType: "excluded"` (verbatim), `changeKind: not-textual`, `changeReason: "the provision is carved out or disapplied in some respect; the words of the Act are not changed"`, `thisEndProvision: section-3`, `source: tna-bulk-amendments`, `origin: official`, `quote: null`.

**What a screen prints** (`describeEffectRow`):

> amends · “excluded” · Victims and Prisoners Act 2024 section-69 → section-3 · **DOES NOT CHANGE THE WORDS** — the provision is carved out or disapplied in some respect; the words of the Act are not changed · legislation.gov.uk’s official record

**The count line it sits under** (`describeEffects`):

> 35 amends: 31 change the words of the Act; 4 do NOT change the words (3 excluded or disapplied, 1 applied, modified, restricted or extended). 35 from legislation.gov.uk’s official record. 1 is recorded against the Act as a whole.

**What Lex receives** (`statute_effects`): the same row with `sub_type: "excluded"`, `changes_the_words: "not-textual"`, `reading: "…the words of the Act are not changed"`, `origin: "official"` — plus `per_type: { total: 35, change_the_words: 31, do_not_change_the_words: 4 }` and three standing rules (*say how many change the words and how many do not; an official row has no quotation; state the freshness sentence*). Told "35 amendments", the model would have overstated by 4.

Equality Act: the same property for `applied by S.I. … (as amended)` — 2 rows of 705 are `applied…`; the check asserts on the SQL count because those rows sort after the 500-row cap and an assertion on rows alone would be vacuous (C3).

## 5. `check:names-negative` — retired

**Why.** It proved "a guard can fail" by `UPDATE`-ing a real row of the 15-million-row production `corpus_sections` into the defective state, reading the guard, and rolling back. Always rolled back, and still: row locks on a table the ingest fleet writes to, and one process death between the `UPDATE` and the `ROLLBACK` is a corrupted production row. A check that must damage production to show it would notice damage costs more than it proves.

**Replacement** — `check-names-controls.ts`, same five guards, **zero writes, and zero possible**:
- the guard SQL runs over a `WITH corpus_sections AS (VALUES …)` fixture (a CTE shadows the table for one statement): a healthy row must read 0, healthy + defective must read exactly 1 → **5/5 fired**;
- the session is `BEGIN READ ONLY`, and the check asserts the server refuses a write;
- **the control the brief asked for:** a lookup of a corpus name that cannot exist on the real table (indexed, 25 ms) comes back **`no-match`**; a malformed lookup comes back **`failed`**; a real corpus comes back **`match`** — three tagged outcomes, asserted different, so an error cannot be read as an empty answer;
- a **drift assertion**: the five guards are copies of `check-names.ts`'s live half, so each must appear (whitespace aside) in that file — the one place a source assertion is the right instrument (§25).

Result: **5/5 guards fired · 20 assertions over 15 fixture rows + 1 live row read back (writes: 0, by construction).** If a write-path test is ever genuinely required it runs against a copy.

Interpretation call: the brief says "a name that genuinely cannot resolve". `check-names` has no resolver, so I read "name" as the corpus name on `corpus_sections`; the unit-level "no FRBRname → null, not a placeholder" case is already in `check:names`.
