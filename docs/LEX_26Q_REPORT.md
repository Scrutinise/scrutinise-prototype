## The finding that shaped the sprint

The brief says "cause attacked — already recorded on each action". **It was not.** An action row had no title, heading, cause, avenue, sequence, status, number or merge field, and the one place a cause number ever appeared — a gap-check suggestion — was **thrown away when the suggestion was accepted**. So the cause facet, the coverage grid and the "ignore causes everything attacks" rule had nothing to stand on, and the gap check's free test had been a keyword match on word stems. Fixed at the root, in this order: **a recorded cause link** (`targetCauseIds`) → accepting a gap suggestion now **records its cause and avenue** → "Classify with Lex" proposes the link for every other action → the free gap test **reads the recorded link first** and falls back to words.

## Decisions I took (the brief left them open)

* **Ruled-out and merged-away actions leave the documents, the kernel text, the costing, the gap check and Lex's snapshot. Parked ones stay in them** — parking defers, it does not drop. (Every reader of "all actions" — ten of them — now reads LIVE only.)
* **A rebuild no longer deletes actions the user has worked on.** It used to delete every Lex-written action, taking titles, headings and merge history with it, silently, on every re-run. Rows carrying any user structure are now **archived** ("superseded by a rebuild", restorable); untouched rows are deleted as before.
* A **database trigger** numbers every new action, because six different code paths create them and one forgetting would leave an action nobody can name.
* "Specific enough?" and "implementer" are derived from existing fields, not new columns.
* A heading's "show/hide" hides the rows and keeps the header and count (the 26-D behaviour).
