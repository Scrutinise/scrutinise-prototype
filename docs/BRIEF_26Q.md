# BRIEF — LEX 26-Q: making a long list of coherent actions workable

**Thread:** LEX. **Written:** 4 October 2026.
**Source:** Charlie, starting on Coherent Actions with a long, unsorted list.

## §0 — Run mode

**Continuous.** Diagnose, record in the CHANGE_LOG, proceed. Batch the report. **Stop only for** spend
or scope. ⚠ **Reuse before building**: ideas grouping (26-D), the guiding-policy merge (25-P/26-L), the

---

## §1 — Titles

**1a.** Every coherent action has a **short title**, editable, shown first.
**1b. "Title these for me"** — Lex drafts a title for every untitled action in one pass, as proposals
the user accepts or edits. ⚠ **Titles say what the action does, not what it is about** — *"Publish
every named owner's measure"*, not *"Transparency"*.

## §2 — Titles-only view

**2a.** A compact view: one line per action — title, heading colour trim, and small facet labels (§4).
**2b. Click a title to open the full action in place**; click again to close.
**2c. Drag to reorder**, order persisted, same mechanism as the ideas list.
**2d. Multi-select** with checkboxes → bulk actions: assign heading, park, rule out, merge.
**2e. A dropdown on each line** to assign it to one of the user's headings.

## §3 — Headings

**3a.** The user creates headings — *legislation, operational, legal issues, practical*, or any other
scheme. **One heading per action**, shown or hidden as a group, with a count. Reuse 26-D.
**3b. Colour per heading**, as a trim on each action in the group. ⚠ **Never colour alone**: the
heading name appears on the line, and the palette differs in **lightness** as well as hue — Charlie is
colour blind.
**3c. Suggested starting headings for an idea come from its guiding policy.** Charlie's names four
binding links — *duty and means locked together · consequence · brevity of goals · the first
appointments at the top* — plus transparency and transition. **Lex offers these as headings; the user
accepts, renames or ignores.**

## §4 — Facets, so the list can be re-sorted without re-grouping

⚠ **One heading per action is the user's structure. Facets are the platform's, and allow several
sorts at once.** Lex assigns them in one pass as proposals; the user corrects:

- **Avenue** — legislative / organisational / financial (already evaluated by the build).
- **Cause attacked** — already recorded on each action.
- **Link secured** — which of the guiding policy's binding links it protects.
- **Sequence** — now / next / later; and *must come before* another action.
- **Implementer** — who does it.
- **Specific enough?** — has draft text or a named implementer, or not yet.

**Switch the list's grouping to any facet with one control** — *by heading* (default), *by cause*,
*by link*, *by avenue*, *by sequence*.

## §5 — Merge and compare

**5a. Merge one action into another** — the guiding-policy merge, with its four verdicts: merge /
one contains the other / sequence / contradicts. Enhanced action keeps both originals beneath it,
clickable; the absorbed one is archived.
**5b. "Find duplicates"** — the near-duplicate ranking from "How these relate", **leading with the
closest pairs** and a Merge button beside each. ⚠ **Ignore shared causes every action attacks**, as
26-L §9 did for policies.
**5c. Compare two** — select two, see them side by side with Lex's verdict on how they relate.

## §6 — Two views that show what the list is missing

**6a. The coverage grid: actions × causes.** A table — rows the causes, columns the actions or headings
— with a mark where an action attacks a cause. ⚠ **An empty row is a cause with no action**, which is
the gap check's free test made visible.
**6b. The sequence view.** Actions laid out now / next / later, with *before* arrows. Rumelt's
proximate objectives: **what is achievable first and unlocks the rest.**

## §7 — Park and rule out

Same as guiding policies: **Later phase** parks an action under a collapsed header; **Rule out** with
a reason, restorable. Neither deletes.

## §8 — Lex, through its tools

Everything above is reachable from the chat: *"title these"*, *"group these by cause"*, *"which of
these are duplicates?"*, *"put 7 and 12 under Transparency"*, *"what has no action against it?"*.
⚠ **Assigning headings and facets is free-tier; merging and ruling out ask first.**

## §9 — Acceptance criteria

- Every action can carry a title; Lex can title all untitled ones in one pass.
- Titles-only view opens an action in place, drags to reorder, assigns headings from a dropdown, and
  supports multi-select bulk actions.
- Headings carry a colour trim **and** a visible name; the palette differs in lightness.
- Facets are assigned as proposals and the list regroups by any of them.
- Merge uses the guiding-policy mechanism and keeps originals; "Find duplicates" leads with the
  closest pairs.
- The coverage grid shows any cause with no action; the sequence view shows order and dependencies.
- Park and rule out are restorable; nothing deletes.
- Every write proved on a scratch idea, then seen on Charlie's screen.
